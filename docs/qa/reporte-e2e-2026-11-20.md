## Cómo correrla

```bash
cd apps/web
npm run test:e2e            # = npx playwright test
FORCE_LOGIN=1 npm run test:e2e   # ignora sesiones guardadas (<20 min) y vuelve a iniciar sesión
```

- Proyecto `setup` (`tests/e2e/auth.setup.ts`): un login por rol (`admin`, `admin2`, `doctor`, `superadmin`) guardado en `tests/e2e/.auth/<rol>.json` (ignorado en git). Reintenta con espera si el login responde 429.

- El login correcto de superadmin por UI (`01`) se salta (skip) si recibe 429; el login correcto ya queda cubierto por `setup`.

## Bugs de la aplicación

### BUG-01 — `<main>` anidado en todas las páginas del área autenticada
- Severidad: baja (accesibilidad / HTML inválido).
- Pasos: iniciar sesión como admin, abrir `/inicio` (o cualquier ruta de `(app)`), inspeccionar el DOM.
- Esperado: un único landmark `main` por documento.
- Obtenido: `main > main`. `apps/web/src/app/(app)/layout.tsx` envuelve `children` en `<main>` y las páginas renderizan además su propio `<main>`. Lectores de pantalla anuncian dos regiones principales.
- Evidencia: `docs/qa/evidencias/BUG-01-main-anidado.png`; el test `02-navegacion-admin.spec.ts` "`<main>` no está anidado" la reproduce.
- Tipo: bug de la app (el test es correcto; falla de forma determinista).

## Observaciones (no son bugs confirmados)

- `/verificar/<código>` con un código con formato válido pero inexistente responde **200** con "Código no válido" (no 404). Probablemente intencional para evitar enumeración; se prueba el mensaje, no el status.
- Una orden con "Tomografía 1 zona" pasa a Tomada sin estudios vinculados ("Aún no hay estudios vinculados"); el vínculo orden-estudio parece manual desde Estudios. Confirmar con producto si debe crearse automáticamente.
- El login limita intentos (429 tras pocos logins en poco tiempo); la UI muestra el mismo mensaje genérico "Correo o contraseña incorrectos" para 429 y credenciales erróneas (UX menor: no distingue "demasiados intentos").
- La página `/resultados/<token>` muestra el informe solo como enlace de PDF y "0 estudios"; no se verificó el visor de imágenes del paciente (sin estudios cargados en la orden de prueba).

## Fragilidad de tests (no son bugs)

- `getByRole("checkbox", { name: "Panorámica" })` coincide por subcadena con 6 paquetes: se usa `exact: true`.
- La franja de agenda tapada por una cita no es clicable (comportamiento esperado de la UI): la cita cruzada se prueba abriendo una franja libre y cambiando "Inicio" en el diálogo.
- El odontograma no expone la condición por ARIA; se verifica por el color (`rgb(220, 38, 38)`) de la pieza tras recargar.
- Un `toHaveURL(/\/ordenes\/[^/]+$/)` ingenuo coincidía con `/ordenes/nueva`; se excluye con lookahead.
- Fallos intermedios tras el redespliegue: ninguno atribuible a él; no hubo que reintentar.
